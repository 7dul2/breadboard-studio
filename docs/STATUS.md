| S4.4 网络时间线与断点 | 完成 | 网络监视只能回答「现在是什么」，回答不了「刚才那一下发生了没有」——500 µs 的脉冲在数值表里看不见，画成方波就一目了然。数字网络内核记录每次跳变，经**独立协议通道** `net-trace` 送出（排队而非合并：合并掉一条边就是时间线上的一个洞）。三处都有界：内核缓冲 8192 条、控制器保留 4000 条、面板只画最近 2 秒与最近活动的 8 条网络；任何丢弃都会计数并在面板上写明，绝不静默抹平。断点做成「点一下网络名，下次跳变即暂停」——检查放在 drain 时而不是内核里，因为在 settle 中途暂停会留下解到一半的网络；代价是停在含该边的那个 tick 末尾而非边上，而时间线仍按真实时刻画出那条边。新增诊断码 `breakpoint_hit`(info)。单测 10（时间线几何 6、内核边记录 2、断点 2），e2e 2。变异验证：内核不记录跳变后时间线 e2e 失败。 |
| S4.3 LTR390 与 SEN66 | 完成 | 补齐 `environment_node` 里另外两个传感器，顺带把三种 I²C 寻址形态都建了模：SHT4x 是 8 位命令字，**LTR390 是寄存器指针**（写地址、读时自增），**SEN66 是 16 位命令字 + 每个数据字带 CRC**。照真实库写的程序因此能跑通，而不是只对某一种形状有效。LTR390 的原始计数经数据手册的增益与分辨率表换算，改 `ALS_UVS_GAIN` 读数真的会变；只有被选中的模式（ALS/UVS）会转换，忘记设 MAIN_CTRL bit3 就读 UVS 得到 0。SEN66 需要先 `0x0021` 启动并等一个测量周期，提前读 NACK 并提示轮询 `0x0202`；九个量各自独立滑杆，不强加 PM1≤PM2.5≤PM4≤PM10 的物理约束——仿真器只如实报告滑杆的值。命令字、寄存器表与换算全部标注未经实物验证并由测试钉死。单测 15（LTR390 8、SEN66 7）。**BMP390 仍无驱动**：博世的补偿需要 21 字节标定系数与多项式反解，凭记忆写一个 20 系数的多项式风险远高于写错一个命令码，需要对着数据手册单独做。 |
| S4.2 SHT4x 传感器与属性滑杆 | 完成 | `sensor.sht4x@1` 是**第一个真正应答 I²C 读事务的器件**——此前全仓唯一的 `onI2cRead` 是 OLED 的，永远返回 null，所以读通路有单测和时序公式却从没被任何器件走通过。驱动如实建模「测量要花时间」：命令立即 ACK，但结果在转换完成（高精度约 8.3 ms）之前不存在，提前读就 NACK 并给出可操作提示，忘记 `sleep` 的程序在这里失败的方式和在实物上一样。命令编码与换算公式取自数据手册、**未经实物验证**（与 SSD1315 同状态），由测试钉死：CRC-8（poly 0x31 / init 0xFF）、`T = -45 + 175·S/65535`、`RH = -6 + 125·S/65535`。滑杆范围进目录（`SimulationControlDef.range`：min/max/step/default/unit），因为 −40…125 °C 是这个元件的属性，界面不该知道 SHT4x 是什么；滑杆渲染在右侧仿真面板而不是画布，沿用 M-S2 跳过画布 slider 的判断。单测 11（驱动 8、整链路 3），e2e 1。变异验证：让滑杆不发送控件事件后 e2e 失败。 |
| S4.1 电阻导通与分立 LED | 完成 | `GPIO → 电阻 → LED → GND` 这本入门书第一个电路，此前 **LED 永远不亮**：串联电阻在导通图里是断路。定义新增 `conduction`（二端无源件），连通性分成 `full`（电流能过去）与 `direct`（同一电学节点）两层，`output.led@1` 驱动按「阳极高、阴极低」判亮灭，颜色取自 `params.color`（快照新增 `SimDeviceSpec.params`）。顺带补上一个真实缺口：接地网络在数字域里原本是 `Z`，现在解析为强 0——接地网络从不被驱动，所以从来不会被 settle，值一直悬空；这正是 LED 阴极接地却不亮的原因。单测 17（导通与阻值解析 9、LED 驱动 5、整链路集成 3）。实测：夹具加一个 220 Ω 与一只绿色 LED，程序驱动 GPIO5 时 `intensity` 为 1，拉低即灭，`full.connected('mcu.GPIO5','led1.A')` 为真而 `direct.connected` 为假。 |

## 已知限制

- 内置定义几何均为 `approximate` 或 `unknown`，未经实测；DevKit 排距、转接板针序、SEN66 峰值电流、电源模块能力都需要用户填写。
- 供电只做资料数值比较；不检查 I²C 上拉、GPIO 复用、总线电容；不做三维碰撞分析。
- 830 孔板轨道断点按 MB-102 常见做法建模，实物可能连续。
- 自动排线依赖目录的引脚角色，不会猜测无源/未知引脚；“全局优化”是在给定目标函数下的搜索：网络超过 7 个节点或电源轨超过 10 段时改用启发式，走线顺序是局部搜索，报告中的 `exhaustive` 会如实标注；密集线束仍可能需要手动整理拐点。
- 只支持 2.54 mm 栅格与 90° 倍数旋转。
- 数据仅存于浏览器 localStorage；无云端同步。
- 仿真只做到阶段 2：ESP32-S3 的 GPIO/板载 RGB/BOOT/RST 与 TTP223 触摸都有行为，但 I²C 一律返回总线不可用（`i2c_bus_unavailable`），OLED 还没有驱动（报一次 `unsupported_device`），所以夹具的屏幕仍是黑的。I²C 与 OLED 是 M-S3。
- Studio TS 只做语法转译，不做类型检查：写 `.ts` 不等于有类型保护，类型错误要到运行期才暴露为 `program_runtime_error`。
- 死循环保护不可恢复：预算耗尽会终止当前 loop 并进入故障态，只能复位，不能续跑。
