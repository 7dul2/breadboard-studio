## 0. 现状核查（先确认问题成立）

我把当前实现读了一遍，并在本地起服务用真实 DOM 量了一遍。三条反馈都成立，另外发现三条当前就是错的问题。

| # | 结论 | 证据 |
| --- | --- | --- |
| ① | **UI 里没有"焊接"这件事** | 中区工具栏只有 `选择 / 接线 / 平移` 三个工具（`Tool = 'select' \| 'wire' \| 'pan'`）。全仓 UI 源码里"焊接"两个字只出现在视图菜单那个翻转按钮上。放元件到洞洞板 = 库卡片 → 点孔位，和放到面包板是**同一个动作、零提示**；连线两个焊盘 = 接线工具，也零提示。 |
| ② | **翻面是全局的** | `Canvas.tsx:1256` 在**整个场景 group** 上套 `scale(-1 1)`，翻面状态是 `view.side` 一个布尔值。翻一块板，所有板、所有元件、所有导线一起镜像。 |
| ③ | **翻面后元件不压暗、引脚不高亮** | 焊接面实测 `g.component` 的 computed `opacity = 1`；引脚渲染走的是和元件面完全相同的分支（`scene.ts` 的 `componentScene` 里没有任何 side 概念）。 |
| ④ | **（新发现，bug）翻面后所有文字变成镜像字** | 实测焊接面 `text.board-name` / `.board-label` 的 `getScreenCTM().a < 0`，即左右翻转。孔号、行列标签、板名、元件名、导线编号在焊接面全部反着写。 |
| ⑤ | **（新发现）两块板时翻面把它们的位置互换** | ②的量化证据：两块洞洞板下翻面，`bb_1` 的屏幕 x 从 321 → 690（+369px），`bb_2` 从 690 → 321（−369px）。因为镜像轴取的是**全局 bounds 中心**。截图 `tmp/ux-two-boards-front.png` / `ux-two-boards-solder.png`。 |
| ⑥ | **（新发现）库卡片默认态误报"尺寸无效"** | 洞洞板详情卡里列数 `18`、行数 `24`（就是默认值，用户没改任何数字），下方却显示"尺寸无效：列数 5–120，行数 1–24。"实际"添加面包板"按钮可用。根因：`Library.tsx:284-293` 的 `planDef` 依赖 `plan`，而 `plan` 只在 `planChanged` 时非空，于是默认态渲染走"尺寸无效"分支。**同一个 `null` 表达了"没改过"和"算不出来"两种情况。** 截图 `tmp/ux-library-card.png`。 |

另外两条与体验相关的现状：

- 用导线接到**已被引脚占用**的焊盘时，`isSolderableBoard()` 让它静默通过，没有任何"这是焊在同一个焊盘上"的反馈。
- 洞洞板上元件**每个排针都必须落在孔里**，否则报 `pin_not_on_hole`（error）。剪掉/悬空的引脚在实物上是常态，见 R4.5。

### 一处需要修正的原判断

R1.4 原先写"库卡片上把『每个焊盘独立、需自行桥接』讲清楚——现在界面上看不到"。**这句是错的**：截图 `tmp/ux-library-card.png` 显示卡片上完整呈现了定义描述，含"每个镀锡焊盘独立…孔间通过导线或焊锡桥接…孔号使用大写行标签，如 A1、X18。"

但**卡片里一个字都没提"翻面/焊接面"**——用户找不到焊接入口，这段文案没帮上忙。修 R1.4 时按这个事实改。

## 2. R1 · 让"焊接"看得见

### R1.1 「焊接」工具（P0）

中区工具栏加第 4 个工具 `solder`，**仅当设计里存在洞洞板时出现**（否则是噪音）。快捷键 `S`（`V/W/H/L/F` 已被占用，`S` 空着）。

- 光标态：十字 + 落点焊盘预览。
- 悬停焊盘：显示孔地址与状态 —— `空闲` / `已焊 ttp224_1.VCC` / `已接线 w3` / `已桥接`。
- 单击焊盘：选中该焊盘并切到右栏「焊接」面板。
- 拖动两个焊盘：建立焊锡桥接（R1.3，本轮做）。

**为什么是工具而不是继续复用放置**：放元件和焊接是两个心智动作。现在库→点孔既是"放"又是"焊"，用户不知道自己在焊。工具化之后，"焊接"在界面上有一个可指的位置。

**验收**：设计里没有洞洞板时看不到这个按钮；有洞洞板时点一下进入焊接工具，悬停焊盘能看到状态文案。

### R1.2 「焊接」面板（P1）

右栏（现为 `属性 / DSL / 接线向导`）新增第 4 个标签页「焊接」，仅在有洞洞板时出现。

内容：

1. **待焊引脚清单**：`元件.引脚 → 焊盘地址`，点击定位并高亮该焊盘与该元件。
2. **焊接进度**：`已焊 12 / 共 16 个引脚 · 3 处桥接`。
3. **一句话说明**：点孔位 = 焊引脚；拖相邻两孔 = 焊锡桥接。
4. （P2）**建议桥接**：同一网络内相邻但未桥接的焊盘。

**验收**：清单条数与设计里"落在洞洞板上的排针数"一致；点一条能把视图移到该焊盘并选中。

### R1.3 焊锡桥接作为独立对象（**本轮做**，需 schema 变更）

> ✅ **owner 2026-09-17 拍板：本轮一起做**，不拆到下一轮。额外约束见第 7 节「已决定」。

语义：两个焊盘之间的一坨焊锡，**不是导线**。不参与导线数量/线色/长度统计，不占导线编号。

- **表示**：焊接面画成泪滴状锡桥（短粗、有金属高光）；元件面画成两盘之间的细亮铜迹。
- **电气**：与导线等价地把两孔并入同一导通组 —— 复用现有导通图，只多一种连接来源。
- **校验**：端点必须是焊盘；同一对孔不重复桥接；跨非相邻焊盘的桥接给 warning（实物上做不出来）。
- **成本**：schema 新增 `solder_bridges`（或 wire 增加 `kind`）、迁移、校验、CLI/MCP 的 ops 列表同步、导出渲染。**这是本清单里唯一动设计数据格式的一项。**

### R1.4 引导文案（P1）

- 加入洞洞板后，HUD 或画布角落给一句**可关闭**的提示：`洞洞板：点孔位焊元件引脚；用导线连接两孔即焊锡桥接。`
- 空画布文案现在写死"添加一块**面包板**"（`Canvas.tsx:1280`），只有洞洞板时改成焊接说法。
- 库卡片：描述文字**已经写到位**（"每个镀锡焊盘独立…孔间通过导线或焊锡桥接…"），真正缺的是**关于「翻面 / 焊接面」的一行说明** —— 用户找不到焊接入口，这段文案没帮上忙。

**验收**：只有洞洞板时，空态文案不再说"面包板"。

### R1.5 已占用焊盘要说清楚（P1）

现在 `isSolderableBoard()` 让导线可以静默接到已被引脚占用的焊盘上。这是**特性**（焊接面本来就可以在同一个焊盘上再焊一根线），但必须**说出来**：

- 用接线/焊接工具点到已占用焊盘时，toast 或落点提示：`焊盘 bb_1.D5 已焊有 ttp224_1.VCC，将焊在同一焊点上。`
- 焊接面板里该焊盘显示为"有引脚 + 有导线"。

**验收**：往已占用焊盘接线，屏幕上出现说明性反馈，且设计数据不变（仍允许接线）。

### R1.6 库卡片别再误报"尺寸无效"（P1，独立 bug）

详情卡里列数/行数**没改过**时，不该显示"尺寸无效"。两种情况必须分开表达：

- **没改过** → 显示"按原型号尺寸添加"，或干脆不显示这行说明；
- **改过但算不出来** → 才显示"尺寸无效：列数 5–120，行数 1–24。"

顺带把默认文案从"添加面包板"改成按 `render.style` 区分（洞洞板说"添加洞洞板"）——洞洞板卡片上写"面包板"是同一类措辞问题。

**验收**：打开 `perfboard_5x7` 详情卡，不改任何数字时**看不到**"尺寸无效"；把列数改成 999 能看到。

## 3. R2 · 翻面只翻对应的那块板

### R2.1 翻面状态改为逐板（P0）

`view.side: 'front' | 'solder'` → `sides: Record<boardId, 'front' | 'solder'>`（缺省 = front）。

**仍然是视图态**：不写设计数据、不进撤销栈、不改变文件哈希 —— 沿用现有契约（按钮 tooltip 已写"只影响显示与命中，不写入设计数据"）。

### R2.2 只有洞洞板可翻面（P0）

面包板（`render.style !== 'perfboard'`）不提供翻面入口。焊接面是洞洞板的概念。

### R2.3 文字不得镜像（P0，修 ④）

孔号、行/列标签、板名、元件名、引脚名、导线编号在焊接面**必须正着读**。

镜像板体几何、文字各自就地反向抵消。物理上正确的效果是：列的**位置**左右颠倒了（1 号孔跑到右边），但**标签本身仍然正着写**，并且跟着自己那个孔走。

**验收（可自动断言）**：焊接面下所有 `text.*` 节点都不许是镜像字 —— 用 `getScreenCTM()` 的线性部分判行列式 `a·d − b·c > 0`（转 90° 的针脚名 `a = 0`，所以"`a > 0`"这条只对不旋转的文字成立）；`.board-label` 里 `"1"` 的屏幕 x 大于 `"5"` 的屏幕 x（位置确实颠倒了）。

### R2.4 跟着镜像的对象范围（P0，需你确认）

建议如下，理由是"从背面看这块板"：

| 对象 | 是否跟着镜像 |
| --- | --- |
| 该板的板体 / 焊盘 / 孔 / 丝印 | 镜像 |
| 焊在该板上的元件（`placement.board_id === 该板`） | 镜像（从背面看，左右颠倒） |
| 端点落在该板焊盘上的导线 | 镜像 |
| 其他板 / 板外元件 / 不在该板上的导线 | **完全不动** |

镜像轴：绕**该板自身局部坐标的垂直中轴**（局部 `x = w/2`）。这样翻面后板仍占同一块地方，只是左右颠倒，不会跳走。

### R2.5 命中与几何必须跟着改（P0）

这是本次改动**技术上最硬的一块**，需求上要明确写死，否则会出现"点不到 / 点错"：

- `toMm()` 现在用一个全局镜像轴把屏幕坐标反算回设计坐标（`Canvas.tsx:319`）。多板不同面之后，**没有单一全局轴可用**，必须按指针落在哪块板的镜像区域内，用那块板自己的反变换。
- `pinPoints` / `componentAt` 用的是**设计坐标**（`mm(pin.global_um)`）。镜像板上这些点的屏幕位置和设计坐标不再一致，需要按所属板决定 x 是否取反，否则"线压住元件时把命中让回元件"这条兜底逻辑在焊接面会指错对象。

**验收**：

- 两块洞洞板，A 翻面 B 不翻：点 A 的焊盘选中的是 A 的那个孔，点 B 的焊盘选中的是 B 的那个孔。
- 在翻面的 A 上：放元件落孔、拖动元件、拖动导线端点改接、双击尺寸编辑，行为与元件面一致，无偏移。
- 焊接面选中一个被导线压住的元件引脚，选中的是元件而不是线。

### R2.6 翻面入口（P1）

至少做前两个：

1. **视图菜单**：把当前设计的每块洞洞板列出来，各带一个 `元件面 / 焊接面` 开关，另加一个 `全部翻面`（保留现有全局行为作为快捷方式）。
2. **选中该板后**：右键菜单 `翻到焊接面 / 翻到元件面`，或属性面板里一个按钮。
3. **快捷键** `B`（bridge/背面）：对选中的洞洞板翻面。`F` 已被"适应全部"占用，不要抢。

### R2.7 状态显示（P1）

- HUD 现在只写"焊接面"（`Canvas.tsx:1268`）。改成能表达多板：`焊接面：bb_1`，或 `bb_1 焊接面 · bb_2 元件面`。
- 画布上每块翻面的板角上有一个小面标签，避免"这块到底翻没翻"要靠记忆。

## 4. R3 · 翻面后的视觉层级

目标：一眼看出**哪里要下烙铁**。

### R3.1 元件压暗（P0）

该板上焊着的元件在焊接面整体压暗：板体绘图 + 名称一起，建议 `opacity ≈ 0.28`（做成常量，便于调）。

### R3.2 引脚高亮（P0）

- 引脚（穿过焊盘那一端）用高亮色绘制（琥珀色描边 + 外圈光环，复用现有 `pin-highlight` 的视觉语言），**画在焊盘之上**。
- 高亮的是"穿孔点"，不是整个元件 —— 压暗的元件 + 发亮的穿孔点，才是焊接面该有的图。

### R3.3 焊盘状态分层（P1）

焊接面专用样式，四种状态视觉上要能区分：

| 状态 | 画法 |
| --- | --- |
| 空焊盘 | 铜环 + 孔，整体偏淡（不要抢视觉） |
| 有引脚穿过 | 铜环 + 引脚 + 焊点填充 |
| 有导线焊上 | 铜环 + 线端 + 焊点填充 |
| 已桥接 | 两盘之间的锡桥（R1.3） |

### R3.4 悬停 / 选中覆盖压暗（P1）

悬停或选中的元件恢复不透明，并显示引脚名与焊盘地址。理由：压暗是为了让位给焊盘，但"这个压暗的东西是什么"必须随时能问。

### R3.5 导线在焊接面保持可见（P1）

导线是你要焊的东西，不能被压暗到看不见。建议：**端点在本板的导线正常显示，其余导线略压暗**（而不是沿用 `dimUnhighlighted` 那套 0.16 的强压暗）。

### R3.6 元件面不做反向处理

不要求把焊盘画成"透过孔可见"。保持现状，避免这一轮摊子铺太大。

## 6. 技术影响（供评估工作量，不是实现方案）

- **渲染分组**：`buildScene` 现在把 boards → components → wires **平铺**成顶层节点，元件/导线没有"属于哪块板"的父子关系。要让元件与导线跟着板镜像，两条路：
  - (a) 在 `buildScene` 里把板上的对象挂到该板的 group 下（结构更干净，但改动大、影响导出）；
  - (b) 保持平铺，在 `componentScene` / `wireScene` 里给每个对象套自己的镜像变换（围绕所属板中心）。**建议 (b)**：编辑器与导出共用同一段逻辑，改动面小。
- **`SceneOptions`** 需要增加逐板 side 信息（或一个 `mirroredBoards: Set<string>`）。
- **文字反镜像**：`SceneNode` 的 `text` 需要一个"就地反向抵消"的处理，注意是绕**该文字自身的锚点**做 `scale(-1,1)`，否则文字会跑到别处。
- **命中测试**：见 R2.5，`toMm` / `pinPoints` / `componentAt` 三处都要过一遍。
- **导出**：`packages/render/src/svg.ts` 若走 (b) 方案可自动继承逐板镜像。
- **测试**：
  - 单元：镜像中心计算、文字不镜像、逐板独立（两块板互不影响）。
  - e2e：两板各自翻面；A 翻面 B 不动；焊接面引脚高亮（断言 `pin-highlight` 存在且元件组 opacity < 1）；文字可读性（断言 `getScreenCTM().a > 0`）；翻面后仍能落孔放置、拖动、接线。
